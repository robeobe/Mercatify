# Guard an invariant with an allowlist of what is permitted, never a denylist of shapes

**Context**: `mercatify-labs/src/report/assertNoFigures.ts` exists to stop an agent-written sentence from carrying a number the engine did not compute — the failure `mercatify-labs/SPEC.md` §10 records, where the FinOps agent wrote "net annual saving is €6,000, with a payback period of 24 months" beside a deterministic €21,000 and ~6.9 months. Its first version enumerated the forbidden shapes: a digit with a unit glued to it (`40 h`, `24 months`, `$6,000`). It shipped green, with a full suite behind it. Review then showed it passed `pays back in month 15`, `cost 2043 a month`, `returns 389 per month` and `87 percent` — including the most natural phrasing of the very bug it was written for. The same file skipped structural fields by key *name*, so a model that attached an `id` to a `ProseFinding` — a field that type does not declare — got `"actual saving is $6,000/yr"` through untouched. Rewriting the rule as an allowlist (every digit must sit inside a `{slot}` or directly after a label word such as `wave`, `section` or `figure`) and anchoring the skips to tree positions (`^risks\[\d+\]\.id$`) closed both holes at once.

**Problem**: A denylist is bounded by its author's imagination and natural language is not. Worse, the tests are written by that same author from that same list, so a green suite measures *pattern coverage*, not the invariant — and "the shapes I thought of are blocked" is indistinguishable, on a dashboard, from "the rule holds". Skip lists keyed on field names fail the same way from the other direction: an LLM can attach a field your type never declared, and a name-based exemption exempts it too. Both failures are silent, and both are worst exactly where the guard matters most, because the defect it was written for is usually phrased the obvious way rather than the way the pattern anticipated.

**Rule**: When a guard protects an invariant against text or JSON you did not author, enumerate what is **allowed** and reject everything else; never enumerate what is forbidden. Anchor any exemption to a position in the structure, not to a key name, because the producer can add keys your type does not have. Accept that an allowlist rejects legitimate cases — that cost is the guarantee — and give the author a sanctioned path instead (here: add the value to `facts` and reference it by slot). Treat a guard's own test file as suspect when every case was written by whoever wrote the pattern: add cases written to defeat it, and pin the original defect's most natural phrasing as a permanent regression case. A validator's test count says nothing about the class of input it blocks.

**Applies to**: `mercatify-labs/src/report/assertNoFigures.ts` and `src/report/slots.ts`; every other seam in that package where a model result becomes typed data — `src/critic/validateCritique.ts`, `src/preview/validateScreens.ts`, `src/migration/validatePlan.ts`, `src/om/validateRequirements.ts`, `src/intake/fromBrief.ts`; and the report pipeline specified in `.ai/specs/2026-09-19-mercatify-report-pipeline.md` (REQ-003, REQ-004, risk R10).
